## 1. Architecture Decision

- **Context:** The spec adds a second working mode with no runtime (constitution §3). Everything is prompt material that an agent follows and nothing enforces (A4). Several points the spec left to Plan, each checked against the repo:
  - **Graph.** `aspark-graph` makes a Feature node of every *immediate* `.spark/` subdirectory (`artifacts.py:79`). It does not recurse into nested directories. It flags `*.md` stems that contain `spec`/`plan`/`review`/`qa`/`release` as near-misses (`:142-147`).
  - **Ceremony enumeration.** `/spark` resume and `/next-steps` step 1 treat every `.spark/<dir>/` as a feature (`skills/spark/SKILL.md:21-22`, `skills/next-steps/SKILL.md:33`). No skill or agent enumerates `templates/` or plugin directories (grep, 0 hits). The word `campaign` appears nowhere outside `.spark/` today.
  - **Constitution reach.** 8 of 10 skills cite `constitution.md`. `/increment` and `/peer-review` do not (their agents may).
  - **Precedent.** Constitution §3 already covers a new optional-capability directory: "The same shape applies to any future optional-capability directory". So `campaigns/` needs no amendment.
  - **User rulings (2026-09-30), all = recommendation:** Q1 = A (Inc 2/3 are later feature folders), Q2 = B (two gates for local definitions, D8), Q3 = A (Inc 2's C4 row lives in aSPARK's own constitution), Q4 = B (`/go-live` offers the `/charter` clear step, D9).
- **Decision:**
  1. **Kinds.** Each kind is one file, `campaigns/<kind>.md`. The contract lives in `campaigns/README.md`. Required frontmatter keys are `name` (= filename stem), `trigger`, `goal-kind`, `roles`, `stop-rules`, `budget-defaults` and `phases`. A file missing any key is reported as malformed and not used (AC-2.1). `phases` does the job it does for lenses: the per-phase dispatch source. `stop-rules` lists only the kind's *additions* to Core's four rules.
  2. **Format.** `templates/campaign.md` (≤ 60 lines) holds everything AC-1.1–1.9 requires: goal, veto record, budget, stop rules `SR-1`–`SR-4`, rollback, status vocabulary, the one-goal rule, the goal-change rule and a dated checkpoint log. An instance is created by **copying** the format plus the chosen kind's content into `.spark/campaigns/<campaign>/campaign.md`. The copy is frozen at approval, so the user approves exactly the text that governs the run. Campaign-internal IDs are `S<n>` (slices), `SR-<n>` (stop rules) and `CK-<n>` (checkpoints). None collides with `US-`/`AC-`/`NFR-` or with the graph's `^T\d+$`/`^F\d+$` (NFR-8).
  3. **Instance location: `.spark/campaigns/<campaign>/campaign.md`.** All campaigns share one reserved directory. The effect on the graph is one phantom Feature node, `campaigns`, with all artifacts skipped, however many campaigns exist. Nested instances are invisible to the graph, which is the A6 behaviour, recorded rather than fixed. Stems inside it avoid the five artifact words.
  4. **Activation and dispatch per phase (AC-2.3).**
     - **Inc 1:** activation is only ever an explicit user instruction that names an instance. The instance's run protocol maps Specify (instantiate, then user approval), Plan (Strategist, Archaeologist), Act (Migrator) and Review (Parity Verifier). Each role brief runs as a **fresh general-purpose subagent** through the host's existing Agent dispatch (A8/C9). No `agents/*.md` is added or edited and no skill is touched.
     - **Inc 2:** kinds are discovered by a *rule* ("every `${CLAUDE_PLUGIN_ROOT}/campaigns/*.md` except `README.md`, judged by its own frontmatter"), never by a list of names.
     - **Proof:** T9 and T19 prove dispatch **and** activation for every phase the frontmatter claims.
  5. **Rollback is non-destructive.** Rollback preserves history: a revert commit or a restore committed on top. `reset --hard` and force operations are excluded. The approved rollback path is therefore not a destructive git action under constitution §6. Removing old code (contract) always waits for a fresh user go (AC-5.7).
  6. **Inert standing rule (AC-5.8).** The ≤ 6-line text lives only in the kind file and in instances, under a heading saying it is inert until routing ships. No skill and no constitution line reads it in Inc 1, and README says so (T10). Inc 2 activates it through the constitution pointer.
  7. **Staleness bound (AC-4.4, Inc 2): 14 days.** A flag counts as stale if any of these holds:
     - the instance is missing;
     - its status is not `approved`, `running` or `halted`;
     - its newest `CK-` date is more than 14 days old.

     The bound is unmeasured and labelled so. The check travels **inside the constitution's active-campaign line**, whose shape comes from `templates/constitution.md`. Every ceremony that reads the constitution therefore sees it, and no ceremony needs a per-skill staleness step.
  8. **Project-local definitions (Inc 3): `.spark/campaigns/<kind>.md`.** These are *files* directly in the reserved directory; instances are *directories*. They add no graph node beyond D3's one (AC-6.3), and a local kind stem containing an artifact word shows up as a near-miss, which is recorded. **Two gates (Q2 = B):** aSPARK's own §3 amendment (C3 row in this repo's `.spark/constitution.md`) gates *building* Inc 3; a per-project opt-in field in the *consumer's* constitution, recorded only via `/charter` on the user's confirmation, gates *reading* local definitions at runtime. Upstream wins on a name collision (C8).
  9. **Clearing the active-campaign line (AC-4.2, Q4 = B).** Only `/charter` ever edits the constitution. After the campaign's release, `/go-live` **offers** the `/charter` clear step in the same run and performs it only on the user's explicit yes; on a no, the line stays and D7's staleness check catches it later.
- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | Kinds as `templates/campaign-<kind>.md` | `templates/` holds artifact blueprints for the protected contract. A filename-prefix convention is a closed pattern with no contract README. It mixes "what an artifact looks like" with "what a kind does". |
  | Kinds as lenses, or under `tools/` | A lens is a quality standard switched on by the profile (spec §6 excludes a migration lens). A tool is switched on by installation state. A campaign is switched on by an approved goal. |
  | No `templates/campaign.md`: each kind embeds the format | The AC-1 elements would be copied per kind and drift between kinds, and NFR-1's 60-line format cap could not be measured. |
  | Instance *references* the plugin kind file instead of copying it | A plugin update mid-run would change the rules after approval (breaks C5's "whole spec approved"). `${CLAUDE_PLUGIN_ROOT}` also cannot be resolved in an Inc 1 hand-run outside a skill. |
  | Instance at `.spark/<campaign>/campaign.md` | One phantom node per campaign. Each campaign directory would also look to `/spark` resume like a feature with no `spec.md` and be routed to `/story-time`, and Inc 2 would need open-ended exclusion logic instead of one reserved name. |
  | Single `.spark/campaign.md`, or instances outside `.spark/` | A single root file has no room for per-campaign files and overwrites the history of past campaigns. A repo-root `campaigns/` collides with the user's own namespace and splits aSPARK's state out of `.spark/`. |
  | Role briefs run by existing aSPARK agents (e.g. `reviewer` as Parity Verifier) | Their role files mandate `review.md`/`qa.md` and feature gates, which would conflict with the brief. It also gains no real tool restriction, since `reviewer` has `Edit` (`agents/reviewer.md:9`). |
  | Staleness check written into every ceremony skill | Ten skill edits, a closed-list risk, and NFR-1's per-skill cap spent on one sentence. The constitution line reaches the same ceremonies. |
  | Local kinds in `.spark/campaign-kinds/` or a top-level `.aspark/` | The first adds a second phantom node. The second invents a new top-level convention next to `.spark/`. |
  | Build all three increments in this loop | Inc 3 is gated on an amendment that does not exist yet. One loop cannot end in three releases without muddying the phase map (`skills/spark/SKILL.md:56-58`). |
  | `/go-live` clears the active-campaign line itself (Q4 = A) | A second writer of the constitution besides `/charter`; the user ruled B (D9). |
- **Consequences:**
  - **Easier:** a second kind is one file. An instance is self-contained and auditable. Graph noise is bounded to one node. Inc 1 cannot regress any ceremony because no ceremony text changes.
  - **Harder:** Inc 1 has no automatic activation, so the user must name the instance.
  - **Until Inc 2:** `/spark` resume and `/next-steps` do not know `.spark/campaigns/`. In a repo whose only `.spark/` subdirectory is `campaigns`, `/spark` with no argument would route it to `/story-time`. This is documented, not hidden (T4, T10).
  - **Frozen copies:** fixes to a kind do not reach running instances.
  - **Reserved name:** `campaigns` becomes a reserved `.spark/` name (R7).
  - **Nothing enforced:** every rule is agent-followed (A4, A5).

## 4. Test Strategy

Prompt material has no test suite (constitution §4). The analogue of **unit tests** is structural checks run as real commands with quoted output: `wc -l`, `grep`, `git diff --stat`/`--numstat`, heading presence, and `claude plugin validate .`. The analogue of **integration tests** is dry runs in real sessions against scratch fixtures, negative case first in every increment (T1, T13, T22). `/demo-day` is not a browser run (§8: no browser surface). It is hands-on QA against the installed plugin, and it re-performs at least T11's negative re-run, the T7 migration run and T12 if T12 was declined. Rows QA cannot perform are recorded `not-verified-live`, never passed by reading.

- **US-1 (Must):** structural checks on T2's text for AC-1.1, 1.4 and 1.9. Live checks: AC-1.5 and SR-1 (T3); AC-1.2, 1.6, 1.7, 1.8 and 1.9 (T8). Of AC-1.3's four rules, only "no progress" (T3) and "error twice" (T7, if it occurs) are performed live. The cost-window and merge-conflict rules are **read-verified only**, and QA marks them `not-verified-live` unless it plants them.
- **US-2 (Must):** structural checks for AC-2.1, 2.4, 2.5 and 2.6 (T4, T11). Live: the malformed-key refusal (T6). AC-2.2/2.3: the per-phase table plus diff and grep proof (T9). This repeats the `accessibility-lens` lesson: every claimed phase, dispatch **and** activation.
- **US-5 (Must):** T5 structural. Live in T6/T7: AC-5.1 and 5.6 refusals, and 5.2, 5.3 and 5.7; AC-5.4 only its positive half (one slice per iteration) — `SR-9` never tripped. For AC-5.5, the parity regression and Archaeologist-red are live; double-rollback and budget-out-mid-slice are read-verified only (R4).
- **Instruction-only, not enforced by Core** (stated in docs, never claimed as tested enforcement):
  - budgets and stop rules (A4);
  - the Verifier's "edits nothing" (T7 observes one run's `git diff`, which proves nothing about the next run);
  - "fresh context" (observable only as a separate subagent invocation in the transcript);
  - the token-budget observable (R3);
  - the freeze at approval of §1–§3, the slice list and the parity check (nothing detects a later edit of an approved instance);
  - "told once" (Inc 2).
- **NFR-10:** N/A as the spec states; the untrusted surface is carried by NFR-11 (T8, T20, T26).
