## 1. Architecture Decision

- **Context.** There is nothing to build. The deliverable is a *deletion plus a method*: 14 published figures currently rest on a tool that must stop existing, and constitution §3 (as amended today, `36a3f17`) forbids both a replacement and any new tracked executable code. So the only real design question is **what carries the method once the program is gone**, and it must satisfy AC-2.2 — a stranger executes it literally, supplying no step of their own.
- **Decision.** The method becomes **`jq` one-liners printed in `docs/metrics.md`**, one per figure group, plus the four combination rules stated in prose. Each rule is read off the removed script rather than invented, so the published numbers keep their provenance: union projects on `projects[].id`; OR `reached.*` per `features[].key`; **max per project** on `git.tags/added/deleted` then sum over the union (`spark-metrics.py:646-648`, `:662-664`); sum the `transcripts.*` counters and **union** `days[]` (`:689-706`). Derivation for this feature's own evidence runs from the session scratchpad (never the repo, never `scripts/`) and **only its output** is committed, to `.spark/metrics-script-removal/evidence.md` — the `situational-lenses` / `graph-gates-verification` evidence-artifact shape, which §3's "untracked scratch, output committed" sentence names directly.
  A planning-time hand check over both reports says this rule reproduces the three riskiest figures exactly: tags `12+12+8+9+2+0+9+3+1+5 = 61`, added `114,630`, deleted `12,589` — so AC-2.5's refutation path is real but is *not* the expected outcome. T2/T3 must confirm it by running, not by trusting this paragraph.
- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | Keep a slimmed `scripts/` reader (stdlib, read-only over the reports) | §3 as amended allows **no** `scripts/` exception (Draft B, user's 2026-09-11 ruling), and `marketplace.json`'s `"source": "./"` has no include/exclude — "keep it but don't ship it" does not exist. It is the one option the constitution already closed |
  | Prose-only method: state the rules, print no command | Fails AC-2.2 — the tester has to invent the extraction step, and "a step the tester has to invent fails this AC". Also fails NFR-4's "runnable exactly as printed" |
  | Print a `python3 -c '…'` one-liner instead of `jq` | Re-creates the deleted program inside a tracked document. It would pass a grep and fail the ruling's intent; §3's bar is no new executable code, not no new `.py` file |
  | Dump a per-project table (opaque ids, 13 rows) into `docs/metrics.md` so every figure is addable by hand, no tool at all | Tempting (zero tool dependency, survives `jq`'s absence) but it *publishes a derived snapshot as the method* — the numbers would then have two sources that can disagree, and a reader checking the table against the JSON is checking my transcription, not the evidence. Kept as the fallback if `jq` turns out to be unavailable at QA (risk R3) |
  | Commit the derivation script and have a doc point at it | Direct §3 violation, and it is exactly what this feature deletes |
  | Split the constitution edits into a separate `/charter` run before merge | The user ruled otherwise (spec A2/C2): the repo must never be in a state where the constitution describes a script that is not there |
- **Consequences.** Easier: every figure is checkable by a stranger with one tool that is not ours, and the repo's tracked tree becomes Markdown + JSON exactly as §3 claims. Harder: figures are frozen at 2026-09-09 forever (accepted, A1 — US-7 is the mitigation, not a restoration); `docs/metrics.md` loses ~60 lines of program description and gains commands that must each be *observed running* at QA (NFR-4); and two ACs in the spec turn out to be unsatisfiable as literally written (D1, D2).

## 6. Deviations & Open Conflicts

- **D1 — AC-4.1 is not satisfiable as literally written.** It requires `grep -n 'spark-metrics' .spark/constitution.md` to print nothing, but the **2026-09-11 Amendments row added on this branch (`36a3f17`) names `scripts/spark-metrics.py` four times**, and that row is the historical record of the ruling this feature executes. The spec authorises four edits plus a new row (A2/A8), not the rewriting of an existing amendment. **Planned default:** leave the historical row intact, word the new row without the literal string, and record AC-4.1's constitution clause as **refuted-with-finding** (project `CLAUDE.md`'s valid outcome) with the quote and `file:line`. **Alternative considered and rejected by the user (2026-09-11):** scrub the filename from the historical row — which edits a record, for a grep. **Ruled: the planned default stands** — the amendment record stays intact and the clause closes as `refuted-with-finding`, carrying the quote and `file:line`. The clause was written before that row existed.
- **D2 — AC-4.2's live count cannot stay true.** `git ls-files | wc -l` grows inside this very PR as `evidence.md`, `review.md`, `qa.md` and `release.md` land, so a §8 inventory that matches the live count at T9 is wrong by QA time. **Planned default:** §8 states its counts with the commit they were taken at (the existing "verified 2026-09-11" shape), QA verifies the totals with `git ls-tree -r --name-only <sha> | wc -l` at that commit, and verifies the one time-invariant clause live: `git ls-files '*.py' | wc -l` = 0. Recorded as a documented deviation from the AC's literal command, not as a pass. **Ruled by the user, 2026-09-11: the planned default stands** — the time-invariant clause (`'*.py'` = 0) stays live-verifiable; only the total is pinned to its commit.
- **D6 — `python3` replaces `jq` as the published method** (arose at T6, ruled by the user 2026-09-11). §1 chose `jq` one-liners; `jq` is absent on this machine and `brew` with it, so no printed `jq` command could satisfy NFR-4's "observed to run" or T6's definition of done. The ruling rests on `python3` being present where `jq` is not — AC-2.2 fails if the reader must first install a tool — and on §3's bar being no new tracked executable *code*, which a fenced example command is not. The plan's objection that `python3 -c` "re-creates the program" is answered by scale: the deleted file was 32,654 B of discovery, parsing, merging and CLI; each printed command is a `json.load` plus a set union. Evidence: `evidence.md` Entry 4.
- **D7 — one extra hunk inside §3** (T9). The clause "no new tracked executable code is added — *not while the exception is open and not after it closes*" referred to the deleted exception, so the qualifier was dropped. Same rule, same scope; T9's DoD had asked for no other hunk in §3, and leaving a dangling reference was judged worse. `/peer-review` owns the ruling.
- **D3 — no version bump in this increment.** NFR-1 requires no diff under `.claude-plugin/`, so `plugin.json` stays at `0.8.0` through Act. NFR-2's minor/patch bump belongs to `/go-live`'s release step and is assessed there.
- **D4 — library lens §3 (packaging & footprint) is treated as applying**, against constitution §2's `N/A`. Spec §5 note, accepted by the user at the spec gate; the `/charter` revisit is a follow-up.
- **D5 — this feature edits `.spark/constitution.md`**, normally `/charter`'s alone. Authority: the user's 2026-09-11 ruling (A2) plus §3's own instruction (A8).
- **Observation, not a task.** The approved spec's own A5 publishes `/Users/andreaslottes/aSPARK` in a tracked, public `.spark/` file. NFR-6 scopes its check to `docs/`, and the spec is an immutable record — so this plan neither fixes nor restates it, and keeps `evidence.md` free of absolute paths.
