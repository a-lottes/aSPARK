**AC-1.3 stays unperformed, and the reason is worth stating precisely.** The user gave their go; the environment's permission layer then refused `claude plugin marketplace update aspark`. So the refresh never happened, the `gitCommitSha` never moved, and R1 never got the chance to fire — nothing is known either way about the merge-vs-replace question. What I would **not** do is let the cache's pre-existing `0` `.py` files stand in as a pass: Entry 9 is right that a `find` taken before the SHA moves is a tautology, and the repository's own evidence for "no executable ships" already rests on two things I did verify live — `git ls-files '*.py'` empty, and a fresh clone with zero executable-bit files. Reading the installed files and reasoning about them would be fraud under §8, not a substitute, so AC-1.3 is marked `not-verified-live` and left there.

That single gap does not change the demo answer. It is an environment limitation, not a defect in the work, and the plan and `evidence.md` R1 both anticipate a blocked install refresh as an honest outcome. **`passed`** — with AC-1.3 explicitly unverified and the one open question named for whoever can run the CLI.
