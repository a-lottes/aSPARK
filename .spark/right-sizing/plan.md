## 1. Architecture Decision

- **Context:** No runtime, no build, no test suite (constitution §3/§4) — "implementation" is editing Markdown prompt material, and the evidence is a documented dogfood/dry run, negative case first (§1). The spec asks for two independent rules: a per-project QA-method declaration (US-1) and a citation discipline (US-2). NFR-2 enumerates the added surface as *one* optional constitution field plus reading/writing rules in `/demo-day`, `/go-live`, `/charter`, `qa-tester.md` and `reviewer.md`; **the user extended that enumeration at the plan gate to include `skills/spark/SKILL.md`** (2026-08-29 — see T10 and §5). That enumeration, as extended, is this plan's fence. The one non-human reader, `aspark-graph`, never opens `constitution.md`: a grep of `~/aSPARK-graph/src/aspark_graph/` for `constitution` returns **zero hits**, and `_parse_feature` (`artifacts.py:76-80`) probes only `spec.md`, `plan.md`, `review-report.md`, `qa-report.md`, `release-notes.md`. NFR-1's claim is therefore **verified, not assumed**, and no structure protected by constitution §3 is in this diff's reach.
- **Decision:** Add **`## 8. QA Method`** to `templates/constitution.md` as a new optional section modelled line-for-line on §7 `Delivery & Handoff` — two fields, each with an explicit *Default when absent*: `Browser-observable surface: yes | no` (default `yes`) and `Substitute verification method: <named method>` (default: none — the QA phase asks, exactly as today). Both fields present and non-empty is the only complete declaration; anything else falls back to today's behaviour (AC-1.9). Readers meet it where they already read the constitution: `/spark` step 2 before it gathers QA prerequisites, `/demo-day` step 1 *before* the browser-tooling check, `qa-tester.md` step 1, `/go-live` + `release-manager.md` for the §1 citation. Only `/charter` writes it (AC-1.10). US-2 lands as one compact block in each of the two reading agents — the four AC-2.2 re-derivation conditions verbatim, the name-the-condition rule, and the artifact-wording severity cap. Ten tasks at approval: T1 is the walking skeleton (the field, statically proven inert against the parser), T8 is the **negative case and it runs before any declaration exists anywhere**, T9 the positive case behind a user-confirmed `/charter` amendment. **Four more (T11–T14) were appended by the revision of 2026-08-31; they change no architecture — the same block, in the files that were missed — see `R1` in *Deviations*.**
