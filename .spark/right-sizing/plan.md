## 1. Architecture Decision

- **Context:** No runtime, no build, no test suite (constitution §3/§4) — "implementation" is editing Markdown prompt material, and the evidence is a documented dogfood/dry run, negative case first (§1). The spec asks for two independent rules: a per-project QA-method declaration (US-1) and a citation discipline (US-2). NFR-2 enumerates the added surface as *one* optional constitution field plus reading/writing rules in `/demo-day`, `/go-live`, `/charter`, `qa-tester.md` and `reviewer.md`; **the user extended that enumeration at the plan gate to include `skills/spark/SKILL.md`** (2026-08-29 — see T10 and §5). That enumeration, as extended, is this plan's fence. The one non-human reader, `aspark-graph`, never opens `constitution.md`: a grep of `~/aSPARK-graph/src/aspark_graph/` for `constitution` returns **zero hits**, and `_parse_feature` (`artifacts.py:76-80`) probes only `spec.md`, `plan.md`, `review-report.md`, `qa-report.md`, `release-notes.md`. NFR-1's claim is therefore **verified, not assumed**, and no structure protected by constitution §3 is in this diff's reach.
- **Decision:** Add **`## 8. QA Method`** to `templates/constitution.md` as a new optional section modelled line-for-line on §7 `Delivery & Handoff` — two fields, each with an explicit *Default when absent*: `Browser-observable surface: yes | no` (default `yes`) and `Substitute verification method: <named method>` (default: none — the QA phase asks, exactly as today). Both fields present and non-empty is the only complete declaration; anything else falls back to today's behaviour (AC-1.9). Readers meet it where they already read the constitution: `/spark` step 2 before it gathers QA prerequisites, `/demo-day` step 1 *before* the browser-tooling check, `qa-tester.md` step 1, `/go-live` + `release-manager.md` for the §1 citation. Only `/charter` writes it (AC-1.10). US-2 lands as one compact block in each of the two reading agents — the four AC-2.2 re-derivation conditions verbatim, the name-the-condition rule, and the artifact-wording severity cap. Ten tasks: T1 is the walking skeleton (the field, statically proven inert against the parser), T8 is the **negative case and it runs before any declaration exists anywhere**, T9 the positive case behind a user-confirmed `/charter` amendment.
- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | Put the declaration in §4 Quality Bars, next to `Testing:` | §4 is free prose with no field convention and no *Default when absent* idiom, so AC-1.9's "present but incomplete" case has no crisp shape and a reader must parse prose to find the declaration. §7 is the precedent the spec itself names (C4/A5) and is already read by section name by an agent |
  | Put it in §2 Project Profile, beside the lenses | Proximity invites exactly the coupling C14/AC-1.8 forbids: a mis-typed profile would suppress QA with nobody deciding it. Kept two sections apart on purpose |
  | A new `lenses/no-browser.md` or `templates/qa-method.md` file, per constitution §3's "a new concern is a new file" | That pattern governs *lenses* — checklists passed generically to agents. This is a per-project declaration, not a concern-checklist, and a new template file is new public surface, banned outright by NFR-2 |
  | Let `/demo-day` infer "no browser surface" from the constitution's profile (no `website`, no `web-app`) and skip the field | Infers instead of declaring (AC-1.8), and it is the agent ruling its own gate inapplicable — issue [#13](https://github.com/a-lottes/aSPARK/issues/13)'s anti-rationalization risk, which AC-1.10 exists to block |
  | One free-text `QA method:` field instead of two | Cannot make AC-1.5 checkable: a stray value on a project *with* a browser surface would suppress the live-browser requirement. The explicit `yes`/`no` assertion is what makes suppression impossible there |
  | Edit `templates/release-notes.md` §1 and `templates/qa-report.md` §1 to carry the citation and the non-browser environment | Neither is in NFR-2's enumerated surface, and neither edit is needed: the citation is a *writing* rule (`/go-live` + `release-manager.md`) and the QA Tester already writes `N/A` into §1 environment fields. Leaving it out ships a feature that fails its own S1 at the loop's most common entry point |
- **Consequences:** Easier — the recurring `/demo-day` override becomes a standing fact read once, at the orchestrator *and* at the ceremony; a re-review that already has a cited fact stops re-deriving it. Harder — a *fourth* fall-back path now exists in `/demo-day` (absent / incomplete / declared-but-unperformable / declared-and-performable), and three of the four must be provably indistinguishable from today, which is why T8 is a task and not a footnote. Also harder: the QA Tester's core guard ("never substitute code reading for testing") now needs a stated boundary — a declared method is *performed and recorded*, never read.
- **Adjudicated tension (user ruling, 2026-08-29), recorded so `/peer-review` sees a decision rather than a contradiction:** AC-1.7 lists `/go-live` among the ceremonies that "behave exactly as today", while AC-1.4 changes `/go-live`'s §1 QA-row wording. **Ruling: AC-1.7 is C11's *generic-mechanism* fence** — no ceremony is skipped, softened, merged or given an off switch at any declaration value — **and AC-1.4 is the specific wording rule, which governs the §1 QA row.** NFR-2 naming `/go-live` as a rule-carrying file supports that reading. - **Negative dry run (T8, runs first).** Every touched ceremony — `/spark` step 2 included — exercised in this repo *before* any declaration exists. This is the required evidence, not a bonus: constitution §1 makes it the first thing that runs for an optional capability. Covers AC-1.3, AC-2.5, NFR-4, NFR-6.
- **Gate-integrity diff (T8).** All six gate checklists counted before and after; NFR-6 fails on any delta in count, item or owner.
- **Positive dry run (T9).** The declared path at both entry points, plus the three fall-back paths (AC-1.5/1.6/1.9) as constructed inputs — ambiguity must resolve toward more verification every time. Covers US-1 in full.
- **US-2 is verified by this feature's own loop (T9) — *only once the branch is installed*.** Ceremonies load `${CLAUDE_PLUGIN_ROOT}`, which resolves to the installed plugin cache, **not** the working tree. Round 1's `/peer-review` therefore ran `0.7.0`'s `reviewer.md`, which does not carry the US-2 rule at all (`grep -c` → 0), so this strategy line was **untrue as written at plan time** and is corrected here rather than left standing (review finding F3). Until then US-2 has no live proof, and none may be claimed. Covers US-2.
